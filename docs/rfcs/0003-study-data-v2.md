# RFC 0003：标记与资源任务的数据基础

- 日期：2026-09-13
- 状态：数据基础已实现并通过本地回归；合并、部署及设备结果以 PR 和项目状态为准
- 对应：Issue #8；标记界面 #9、完整今日计划 #10 分别交付

## 范围

为 StudyData 增加 schemaVersion=2、questionMarks 与 resourceTasks，接入现有本机操作日志、跨标签合并、用户隔离、服务端同步及 JSON 备份恢复。保留现有档案、首答/复练、打卡、录音 ID 和音频命名空间。此阶段不新增每日计划界面，不将资源任务当成已完成的学习时间。

QuestionMark 使用 qid，包含 flagged、五类 reason（listening/vocabulary/grammar/evidence/timing）、短 note。ResourceTask 使用稳定 UUID 和现有资料 ID，包含 plannedDate、status、minutes、可选 checkinId。两者都有 revision、mutationId 和 updatedAt。

## 冲突与取消

可修改实体按 revision → 取消优先 → mutationId → 规范化内容的确定顺序合并。updatedAt 用于显示，不以设备时钟决定版本。规范化内容转为 ASCII JSON，保证浏览器比较与 SQLite BINARY 顺序一致。

本机编辑取已观察最大 revision + 1；同 revision 的取消优先，明确再次启用须有更高 revision。flagged=false 和 status=cancelled 都持久化并导出，不能通过删除数组元素实现取消。前后端使用相同比较规则；服务端条件 upsert 原子判断新旧，旧请求可幂等确认但不能覆盖新状态。数据库新表主键包含 user_id 和实体 ID。

替代方案：单纯 updatedAt 会受到设备时钟偏差影响；直接沿用远端覆盖会使取消状态复活。此处选择可审计的确定合并规则，不引入通用协作框架。未观察到的并发重新启用可能由取消胜出，界面后续应允许用户同步后再次明确操作。

## 迁移和备份

旧快照纯函数升级：只补版本和空集合，不产生随机 ID、时间或新打卡。执行两次结果相同。旧资源 note 保留原文，不自动生成任务，不重复累计分钟。分钟继续从 checkins 统计；task.minutes 是预算/描述，完成流程以后关联稳定 checkinId。

新增数据库迁移只创建两张表，既有迁移及 metadata 不改写。旧服务器未返回新集合时保留本机集合。未来不兼容 schemaVersion 必须阻止写入，保留原始快照供升级后处理；远端返回更高版本时按账号持久保存最低版本要求，使刷新及其他标签页也停止上传。

新实体使用复合主键隔离账号。既有 attempt/checkin 表仍保留原主键；导入其他账号已占用的旧 ID 时返回 422 并保留待处理操作，不能假确认成功，也不自动改写旧 ID。

个人 JSON 备份包含新实体及取消状态；恢复按稳定 ID 和同一版本规则合并，不重复产生学习记录。录音备份只有元数据，不包含 Blob；不得信任导入数据中的 uploaded=true。当前账号已有确认副本可保留，否则需要远端确认或显示缺音频。恢复接口先提供代码能力，用户操作界面不属于本次范围。

## 验收

旧数据重复迁移不改变 ID、时间、分钟和首答；跨标签和乱序同步不丢失新实体；取消在重启、旧响应和恢复后仍存在；更高版本可以重新启用；不同账号相同实体 ID 独立保存；真实 SQL 条件 upsert 拒绝旧版本覆盖；导出恢复幂等；非法题目/资源/日期/错因及跨账号关联被拒绝；旧回归继续通过。生产/设备验收与自动检查分别记录。
