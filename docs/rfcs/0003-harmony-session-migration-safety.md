# 鸿蒙账号服务迁移：会话连续性安全设计（候选）

状态：设计中，自动迁移默认关闭。本文不改变认证服务、生产地址或用户界面，也不代表已验证真机续登。

## 当前约束

- v1 Asset 只保存来源、token 和过期时间，没有可信的账号 ID。新服务用 token 返回一个用户，并不能独立证明它与旧服务里的用户相同。
- `AuthSessionStore.load` 在来源不匹配或过期时会清除 v1。`NativeAuthHost` 的 providers、session、华为登录和同步调用都可能在迁移之前读取或清除会话；多个异常处理、401 和退出路径也会清除。单独新增一次非破坏读取无法覆盖这些路径。
- `NativeAuthHost.busy` 在当前进程内协调多个 host 实例；这不能单独证明所有可能进程或旧版应用都遵守同一屏障。
- 本机 SDK 和[华为 Asset API 文档](https://developer.huawei.com/consumer/en/doc/doccenter-references/api/js-apis-asset/)列出单条资产新增、查询、更新等接口。当前未找到成功返回后断电持久性、跨进程顺序或条件更新的明确保证；不能仅凭内存 mock 推断这些保证。
- 候选固定来源必须与实际发布到用户手机上的旧制品及审定后的新服务核对。源码中的当前来源不等于自动证明设备当前来源。

## 最小设计方向

保留原 v1 别名，不在迁移失败、超时或目标返回 401 时删除它。新增独立 v2 别名，把目标来源、token、有效期、状态与唯一代际放在**同一条**加密资产中，作为新的唯一状态记录。所有 native 认证及同步入口必须先经过统一屏障，不能先调用旧 `load`/`clear`。已有未接线的 `peekMigrationLegacy` 只能作为候选输入，不能单独开启迁移。

状态至少需要：迁移待确认、稳定、身份操作待确认、已退出。读取出错、记录损坏、未完成状态和无法核实的状态均关闭自动恢复，不发布 owner；不得把存储错误当作资产不存在。每次注册、登录、切号、退出及其他可能改变身份的操作，在网络请求之前写入身份操作待确认；服务器结果、目标会话和当前操作代际都确认后，再写入稳定状态或已退出状态。失败或结果不确定时保持待确认。所有清理路径必须遵守同一规则，不能因 host 过期或超时清除其他操作的新会话。

迁移期间先建立持久的迁移待确认状态，再验证固定旧来源的未过期 token：仅向经过审定的固定 HTTPS 目标发送请求，拒绝重定向、意外 cookie 和不符合严格 v2 协议的响应。剩余有效期取旧记录与目标证明的较小值，并扣除验证耗时。只有状态写入、当前操作代际和目标证明都成功，且应用仍处于有效生命周期时，才可发布当前进程的 owner 租约。重启后必须重新向目标验证，不能仅依赖本地存储发布 owner。

把状态与新 token 放在同一记录能避免设计依赖两个别名之间的原子提交，但仍需要证明单条记录成功写入后的原子性、持久性和串行化；代码中不可自行假设。若确认不了，保持默认关闭，让用户通过正式登录恢复。保留的 v1 仅供受控恢复，不能由新版自动复活；旧版不认识 v2 屏障，因此降级需要服务端撤销旧入口或其他明确的切换保护。

## 身份和切换前置条件

迁移发布前，需要可审计证据证明：旧侧停写并取得最终一致快照，新旧服务中每个可迁移 `token_hash → user_id` 映射相同；快照之后旧侧不能产生未迁移的账号或学习增量。新端 TLS 和协议验证、固定新旧地址、异常处理及服务端令牌有效性必须同时成立。凭新端自报的 user ID 无法替代这项证明。回滚需处理新侧增量，不能直接重启旧数据库并声称数据连续。

## 验证与发布门槛

1. 官方契约或可审计实现证明持久写入、失败结果与单写者机制；明确跨进程和安装/降级边界。
2. 真实 Asset 设备测试和必要的故障注入覆盖：每次写入前后杀进程或重启、Asset 查询/写入错误、并发 host、旧/新来源不匹配、目标 401/超时/重定向、owner 不一致、短有效期和时钟变化。
3. 覆盖冷启动 providers、session、同步、华为登录、退出及切号，确认失败不删除 v1、不发布 owner，完成退出后旧 token 不会复活；跨设备验证和账户数据隔离独立验收。
4. 核对实际旧制品配置、最终切换映射和回滚方案；完成正式构建与真机验收后再决定是否启用。模拟测试只验证状态逻辑，不能替代平台或部署证据。
