## P1：定稿前必须补齐

### F01 · 口语保存、回放与退出缺少完整设计，失败恢复文案与现有能力相反

证据：`desktop-speaking-day.jpg` 与 `prototype/design.js:27` 只给朗读题、计时、录音按钮和返回练习；`:6` 仅录音前、录音中、权限不可用三态。`:18` 的口语目录只有一个朗读入口，没有五类任务的可比较目录。录音中仍渲染直接 `data-page="practice"` 的返回，`:39` 的通用导航立即切页。这是原型路径缺口，未测试真实录音丢失。

更具体的问题是截图底部及 `:27` 写“保存成功后才可回放 / 导出”。现有 `app/learn/speaking.tsx:38` 在录音完成后允许回听，保存失败时提供重试及“下载录音”保留 Blob；`:26–33` 的退出会先停止、等待保存，失败后才让用户明确选择放弃。新稿不能封死失败时的下载保留途径。规格 `DESIGN-SPEC.md:188` 的一句沿用说明不足以决定这些状态的版式和动作。

修正：补五类任务可达目录；至少补一个带图片或长材料的任务。给出准备→录音→整理/保存→回放/自评/参考表达→再录/记录收获的桌面与手机代表稿。保存失败须可见回听、重试、下载保留与明确放弃风险；录音中/保存中返回走受控退出，不能由通用导航直接离开。保留练习发生时间，不增加 AI 分数或新存储功能。

关闭条件：可从普通目录连续审阅录音完成与失败恢复的 UI；失败时 Blob 的处理和返回顺序在画面及文档一致。无需在设计阶段调用真实麦克风。

### F02 · 模考缺交卷闭环，短句四选项不足以确定听力与长阅读布局

证据：`desktop-exam-silk.jpg`、`prototype/design.js:24` 只有 Part 5 短句、四选项、上下题、保存并退出和折叠20题号。没有“提交整卷”入口；`:6` 未列交卷确认、提交中/失败或截止状态。结果页只可由评审页选择器直接进入，作答画面不能表达如何完成考试。现有 `app/learn/mock-exam.tsx:344–353` 已有提交整卷、未保存答案数量、交卷后不可修改的确认。

常规练习 `:19` 同样仅 Part 5。现有稿未确定题图/扫描页放大、完整 LC 音轨、逐句回听/听写、Part 7 多材料长文在桌面与手机的关系。不能把这些学习内容都交给实施者套短句卡片临时决定。旧制题包在 `:23` 有标签，但两个预检入口都进入 `:25` 的现行题型模板；目前只说明会保留 format，未展示如何保留。现有结果 `:26` 的三个 Part 是明确标注的示意，不是数值计算错误，但尚不足以代表完整结果页。

修正：至少补题图听力与完整音轨、长/多材料阅读的桌面和手机稿，并补一种回听/听写展开状态。补手机答题卡、阅读阶段交卷入口、漏答/未保存数量确认、保存失败及截止提示；退出保存失败时原计时仍可见。补旧制预检显示原 format/声明时长，以及七 Part 结果与原题包/首次或复测身份。只画真实能力，不接私人题本，不改变原截止。

关闭条件：目录→预检→不同材料作答→答题卡→交卷确认→结果→原题解析路径可审阅；退出/交卷失败与原截止的关系有具体 UI。不是要求完成自然两小时实机测试。

### F03 · “两套游戏主题有辨识度”尚未满足，当前窄屏主要依赖色彩和名称

证据：`four-theme-home.jpg` 四卡骨架一致，已有两枚不同的门拱/面具、钟形/丝线纹样，严格说并非完全纯换色；但符号笔画极细、体量很小，主体仍是同一蓝色或莓红卡片。`mobile-practice-silk.jpg` 的页角纹样几乎退到背景中，`mobile-settings-night.jpg` 的游戏预览主要读到色块。`prototype/design.css:5` 普通标题纹样 opacity 为 .22，`:10` 在≤350px把标题与预览纹样都隐藏；320px下两个游戏主题因此只剩配色和文字名称。专注题面干净是优点，不需要在那里增加艺术。

本项是针对用户要求的独立视觉判断，不是 WCAG 或版权合规判定。共用布局与组件完全可保留，问题在主题的身份表达过弱。

修正：让普通页边缘与主题选择中出现可读、统一的原创主题符号体系：空洞主题强调门拱/骨白/洞穴的形态节奏，丝歌主题强调针/丝/钟的不同线形与边缘节奏；小屏保留一个不挤压标题的识别位置。无需回到大场景、角色墙纸或常驻动效。默认日夜不能继承这些符号。同步 `:5` 标题90×70、移动52与规格固定48px的差异，冻结实际尺寸。

关闭条件：提供390与320px普通页、主题预览的同尺度对照；遮住名称后，仍可从形态识别两游戏主题。题面、输入、释义和录音主体保持安静。若作者选择继续只保留色彩气质，应先明确它与本次要求的偏差，不能直接宣告已达成。

### F04 · 资料学习闭环未画出来，“全页面覆盖”仍有缺口

证据：`desktop-library-day.jpg` 只有三个“查看↗”行与一句“资料打开和学习打卡是两个动作”；`prototype/design.js:23` 的 `open-resource` 仅演示提示，没有材料步骤、访问说明、学完记一笔和已学记录的位置。生产 `app/learn/resource-library.tsx:19–28` 已有这些功能。现稿的简洁来自省略一部分现有学习信息，不能在全量重设计中默认丢失。

修正：补一个材料详情/展开稿，包含现有步骤、访问条件、打开材料、学完记一笔、已学次数/分钟；补现有资源打卡后返回原资料的状态，沿用 note 内 `[资源:id]`，不扩展计划编辑模型。另补明确的页面/组件位置索引，指出真实偏好编辑（目标/考期/预算/时区）、三类备份、安装/来源说明、录音历史回放的稿或现有界面保留策略。当前设置 `:29` 只有预算编辑提示和合并“现有导出入口”，不能仅以页面清单证明上述界面已经重新设计。

关闭条件：每个保留入口有可评审布局或明确采用哪个已评审共享模板；材料从打开到记录学习的路径能完整审阅。无须为每条资料重新画一整页，也不新增学习 JSON 恢复 UI。

## 架构与数据边界

书面边界总体清楚，可保留，不需本轮擅自迁移存储：

- 主题 `paper/crystal/hollow/silk` 的兼容表在规格`:338–345`明确；`day/night`只作视觉别名。theme-only、首次云GET竞态、离线与跨标签目标保持已写入`:334,408`。
- 查询/详情快照属于 UI 状态，账号切换清除前账号视图；学习、词库、模考和云题包的保存/同步口径在`:399–418`分开。
- 模考原题包、原考试ID、原截止、首次/复测和退出成功保存再离开，在`:182–186`明确；不把云题包等同成绩同步。
- 录音发生时间和文件引用保留，Native Back的录音100→模考90→图片50→词典30→壳0沿用架构契约；F01要求把这些规则落实成可审阅 UI。
- 不新增学习JSON恢复、错因标记/资源计划编辑、短信认证、云考试记录；读取失败不当空库覆盖，IndexedDB abort与R2/D1同ID风险保持另线处理。
