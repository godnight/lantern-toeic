日期：2026-10-13。评审者：learning_review。阶段：现场代码与使用流程审查；尚未审查第二轮隔离原型。只写本文件，不修改生产源码、题包、用户记录或进程。

## 结论

应按学习意图重建导航和页面，而不是在现有场景卡片上继续精修。首页先回答「今天学什么」和「如何继续」，查词成为常驻入口，练习与复习各有明确的完成/退出闭环，资料库先区分个人题包与外部资料。四套主题使用同一个学习信息架构，主题不改变任务顺序、搜索结果、学习算法或账号边界。

建议第一优先级：清晰任务层级、持久与非持久状态的诚实文案、搜索状态完整、手机返回保留上下文。视觉上的克制不能通过隐藏复习入口、失败信息或数据范围来获得。

## 建议信息架构

### 桌面

左侧固定导航：今日、练习、复习、进度、资料库。左侧上部或全局顶栏设置明确的「查词」入口，点击后进入搜索工作台。查词是单独页面，URL/页面状态应能表达 query、范围、当前词条；不要把词详情永远做成覆盖整站的窄弹窗。

顶栏只保留页面标题/上下文、查词、账号与设置。同步状态用简短文字和图标，展开查看失败项；不能压缩成只有颜色的灯。主题置于「外观」设置，当前主题名始终可核实。

### 手机

推荐五个底部目的地：今日、练习、复习、查词、资料库。进度从首页学习摘要及资料库/个人面板的一致入口进入；需一轮验证用户是否接受进度离开底栏。另一可行方案是维持五栏并让查词成为每页顶部恒定按钮，但查词仍必须一击到达；不要在 390px 底栏塞入六个文字目的地。

名字直接表达任务：今日、练习、复习、进度、资料库；空洞骑士和丝之歌可以装饰页面，不改变栏目的名字或语义。导航图标与文字共同显示，当前项有形状/底衬与 `aria-current`。

子页面使用明确返回：搜索详情返回结果；资源返回当前筛选；练习退出回到来源页，而不是统一回首页。返回恢复输入、范围、筛选、结果数量、列表滚动和焦点。常规题组退出要诚实提示已保存答案与未保存选择；模考沿用已有退出保存和计时保护。

## 页面方案与具体层级

| 页面 | 第一层（首屏主要行为） | 第二层 | 第三层与展开内容 |
|---|---|---|---|
| 首页 | 标题「今天先完成一小组」；一个推荐听读练习 CTA，标明 Part、题量/预算与推荐理由。若存在已保存模考，提供独立继续卡及「计时继续」提示 | 到期词卡和题目复习、错题巩固、今日已记录时间/任务完成 | 目标和考期、小型近7天摘要、口语专项、完整学习记录；不用巨幅场景把今日任务推到屏外 |
| 搜索初始页 | 一个完整宽度输入框，「英文或中文释义」提示；默认统一查询；范围筛选作为次级控件 | 场景词浏览入口、我的生词、到期词卡 | 词库数量和来源说明折叠；近期搜索仅作为可选本机界面状态，未实现时不假造历史 |
| 搜索结果 | 左侧精简列表，显示词头、词性/短释义、来源标签和加入状态；匹配部分可以加重字重 | 桌面右侧详情，手机独立详情；结果计数与「精确结果/相关匹配」分组 | 更长释义、词源、来源和版权详情展开；结果行不展示全部长例句 |
| 单词详情 | 词头、真实音标、可用发音、核心释义；「加入生词本」清晰主动作 | 托业场景搭配/例句（仅实际存在）、词形、多义项 | 来源、词源和相关原创练习。关联题只在真实关联存在时出现 |
| 练习 | 题型/首答或复练、题号、题干/音频、选项、确认；学习时隐藏装饰和全站推荐 | 提交后正确/错误及答案依据，下一题 | 中文解释、逐句回听/听写、词汇；答案未确认之前避免搜索联动鼓励查答案 |
| 复习 | 今日到期数量和一键开始；题目/词卡分段清楚，错题巩固独立标签 | 按到期和错误理由展示列表、下次安排 | 全部已学/未来安排用折叠或筛选；「暂时没有到期」不出现红色欠债状态 |
| 进度 | 近7天实际时间/启动、首答题量；若无记录显示具体起步行为 | Part 首次正确率，同时显示题量分母；复练独立解释 | 手记和周复盘导出、口语录音统计。没有样本不得以 0% 呈现待测，不将样题正确率换成正式分数 |

## 搜索完整状态规范

| 状态 | 可审阅画面与文案 | 行为与实现边界 |
|---|---|---|
| 初始 | 「查一个词，理解一种用法」与输入框；场景词/生词/到期入口 | 不显示虚构用户近期搜索；当前词典空查询确实没有结果 |
| 输入 | 保留正在编辑的字符串，清除按钮可达；中文组合输入期间保持稳定 | `compositionstart/end` 后再触发可见检索变化；不自动聚焦打开软键盘；不每键改路由栈 |
| 首次词典加载 | 输入框仍可输入；「正在准备本机词典，场景词可先查询」；列表骨架局部占位 | 当前是静态文件加载/校验，不宣称网络逐词搜索；无须在每次输入重新展示远端加载 |
| 查询处理中 | 输入与已有结果稳定；小型「正在更新结果」状态可读 | 当前 `useDeferredValue` 无明确 pending 控件。是否后台索引/Worker 由工程方案决定，须标为拟实现 |
| 精确结果 | 第一项词头一致，标签「精确匹配」；直接显示核心义项 | 使用实际 `searchText` 精确词头判断，不以字符串大小写区别排序 |
| 相关结果 | 明确「相关匹配」；前缀/包含词形/中文义项，短释义截为两行 | 当前无拼写纠错。`acommodation → accommodation` 不能出现在“现有能力”演示里；若拟增加本机纠错，单独标拟实现并评审排序 |
| 无结果 | 显示查询词与当前范围；「没有找到」「试试更短关键词或切到全部范围」 | 有筛选时先提供清除筛选；空查询不显示“没有找到”。不得弹出假在线翻译/AI生成释义 |
| 加载失败 | 「词典暂未读入，场景词仍可使用」+「重试读取」；已收藏记录保留 | 重试调用现有 `loadDictionary`，保留输入。历史词条尚不能解析时不能当作用户收藏丢失 |
| 详情 | 顶部返回/关闭、词头、主要释义、发音和加入动作；长义项可展开 | 桌面分栏选中行保持可见；手机返回保留列表位置；缺发音/例句就如实呈现 |
| 加入中/已加入/失败 | 只有本机落盘成功后显示「已加入生词本」，按钮可切换移除；失败保持原状态 | 现有 `store.mark` 返回布尔，不需新增假接口；账号同步可继续等待，不能把本机成功描述为云端成功 |
| 开始词卡 | 显示实际队列数量和「先回想，再翻卡」；揭示后两个自评动作 | 「加入学习」建议保留现有语义为「加入生词本」，不要暗示已自动完成首次复习 |

建议统一查询先对现有合并 catalog 运行实际排序，再用「全部 / 托业场景词 / 我的生词」作为结果范围。到期词卡作为学习入口而非与查询匹配的同权范围；否则空查询和“到期”容易互相隐藏。

搜索范围合并属于本次体验重设计，可复用现有本地词库；无需在线新服务。若调整 `searchWords` 排序，需要实际样本验证英文精确词头优先、中文义项相关、短语多词匹配及多个词义不会吞掉原创短释义。保留来源标签：「托业场景词」「题内表达」「通用词典」；勿把通用词典 84,979 个条目写成“84,979 个托业单词”。

## 完成、退出与数据边界

1. 新学：打开词条 → 阅读实际释义 → 加入生词本 → 可进入该生词词卡。收藏本身不提升间隔。不要新增无意义打勾“已学会”。
2. 常规练习：选择 → 确认 → 本机保存成功 → 解析 → 下一题 → 完成本组 → 如实记录时间/收获；取消打卡不撤销已保存答案。退出时明确「已提交答案保留，当前未确认选择不保存」，返回来源页。若实现持久题组恢复，应列为需另评审的数据/存储变化，当前阶段不得虚构为已有。
3. 错题：来自真实错误记录，不用“收藏题目”冒充错题；首答与复练并存。退出保存行为同练习。
4. 词卡复习：翻卡 → 记住/没记住 → 本机保存成功才切到下一张；间隔维持现有规则，提前反复作答不升级。
5. 模考：预检媒体 → 用户确认试听 → 开始立即计时；本机答案状态明确，退出继续计时，恢复校准；保存失败不得伪装“安全退出”。“继续考试”卡只由真实 active attempt 支撑。
6. 账号：学习称呼只是 profile name；「当前账号」与「本机模式」另行说明。生词、听读/口语记录、题包/考试备份各自独立；新界面可以统一入口，不合并文件格式或数据模型。

## 手机与桌面适配细节

- 桌面搜索采用列表/详情并列（建议列表约 360–420px，详情使用余下空间，正文不超过约 70 个英文字母宽）；选择词条不使列表跳回顶部。横向空间不足时切单列。
- 手机详情采用完整页面或全高面板，返回按钮在顶部；不以小高度弹窗叠加软键盘。主要义项和加入动作易找，完整释义滚动，不截断词源以冒充完整。
- 390px 首屏允许一个主动作加两条次任务。安全区计入固定底栏；软键盘出现时搜索输入保持可见，底栏可临时收起，结果区域使用实际可视高度。不要让虚拟键盘挤压词详情动作成重叠层。
- 长单词允许自然换行，词头英语 `lang=en`；长中文释义两行摘要加详情，多义项序号清楚。不得以强制缩小字体避免溢出。
- 卡片行的收藏按钮具有独立点击区域与状态，不能点星同时打开详情。列表不是整行嵌套另一个按钮。
- 搜索页滚动、词条详情滚动与练习题干滚动各自独立；每屏最多一个主要滚动区，避免手机多层滚动争夺手势。
- 四套主题的字体、文字级别、布局与按钮语义相同；主题只变 token 和有限装饰。默认日/夜不得出现角色、游戏地名、游戏意象的导航缩略图。

| 搜索“近似” | 相关义项搜索已经存在，拼写纠错没有 | 视觉稿可能混画模糊推荐 | 统一叫「相关匹配」；仅精确/前缀/词内/释义相关当前可实现。纠错单独列拟实现 |
| 首页口语 | 主要学习功能要保留 | 本次12月听读优先，等权口语分散注意力 | 首页口语降为次级，练习页口语完整保留；勿未经数据支持改学习算法 |

## 第二轮原型评审门槛与未解决项

原型至少要有：首页、新学/查词结果/详情、练习题与提交解析、复习词卡/题目、进度、资料库；桌面与手机；四主题。每一页需明确示例数据，未连生产账号、无保存/云接口。演示加载/错误/无结果可以是明确标注的状态切换，不可混入“真实调用成功”。

第二轮我会验证：

- 首页是否五秒内能找到今天主任务、复习入口和当前真实继续路径；手机不被海报推到第二屏。
- 查词初始、输入、准备词典、精确、相关、无结果、失败重试、详情、加入中/已加入/失败是否完整；无拼写纠错能力是否诚实标注。
- 搜索详情返回后输入/范围/滚动是否保持；中文组合输入、软键盘、长词头和长义项是否有具体方案。
- 练习退出与保存、答后解析、完成打卡，模考恢复和计时是否沿用既有边界。
- 默认日/夜是否脱离游戏元素，另两套主题是否在搜索、图表、表单、错误/空状态上同样自洽。
- 资料库的云端/本机/考试记录和外链/原创资源是否不混淆。

未解决：手机进度目的地的最终安排；常规题组是否拟持久恢复（当前不具备，不应在第一阶段变成额外数据工程）；统一查询的具体分组/排序样本；所有示例的字数与缺字段边界；真机软键盘/折叠屏/返回链路；线上最新部署与当前可视界面的确认（主代理负责）。本轮没有产品阻塞，以上可在隔离原型中收敛。
