# 微光托业界面重设计：独立工程与无障碍审查

日期：2026-10-13。阶段：方案前的源码审查；待代表性原型第二轮复核。审查者角色：独立工程 / 无障碍。此文档是审查意见，不是生产合规、真机验收或发布证明。

## 结论与必须进入方案的修订

整体重新设计可在既有共享 React 产品上实现，无需扩展认证、题包格式或学习算法。建议通过「统一结构 + 四套语义 token + 有边界的装饰」实现，四套主题共用导航、组件尺寸、状态和阅读面板。第一阶段可以批准制作隔离原型，但原型必须明确覆盖搜索返回、输入法、长文本、保存失败和离线边界，不能只展示成功态首页。

五项优先修订：

1. 将搜索设为持久上下文：查询、范围、筛选、已展示数量、结果列表位置和来源页应可在详情返回及导航返回时恢复；手机软键盘收起后仍回到原结果。不同账号的上下文和收藏不可混用。
2. 将「答案已保存」「时间已记录」「录音已保存」「等待同步」拆开。退出练习必须说明已保存到哪一步；未提交选择不能显示为已保存。退出模考沿用先保存中断标记、失败留在当前页的现有闭环，绝不暂停或重置原截止时间。
3. 正文和题面使用不透明阅读面板；游戏人物、雨、丝线和高光只在低密度页首或主题预览出现，远离题目、输入框、答案、错误提示及搜索结果。默认日间和夜间无游戏装饰。
4. 搜索必须展示初始 / 加载 / 部分可用 / 结果 / 无结果 / 失败重试 / 收藏保存失败 / 已加入状态。当前没有例句、助记或离线发音的词条，不得用占位数据或可点的假入口冒充可用。
5. 所有四主题都按同一可访问性清单复核；只更换整页颜色或图片并不能证明合格。代表稿至少含 320 / 390 CSS px 手机、1440 桌面、200% 文字放大和软键盘场景。

## 搜索与学习退出的设计契约

**搜索。** 桌面可列表 + 右侧详情，手机可独立详情页 / sheet，但不嵌套双层滚动。结果返回恢复列表位置、query、mode、filter、category、limit；进入关联练习后可返回同一词条 / 结果。搜索输入保留可见标签；输入法 composition 期间不提交、不清空、不抢焦点。明确 Enter 的作用，若采用即时搜索只在 composition 结束后宣布结果；不能把英文逐字输入每次都播报为 alert。软键盘开启时结果仍能滚动，固定底栏不得盖住输入或清除按钮；详情用动态 viewport + safe area 适配。长词、长中文、8 条长释义、来源 URL 可换行，列表可节选但详情完整。

**状态。** 加载显示「词典加载中，场景词仍可查」，失败显示真实原因与重试；查询零结果不当成加载完毕或离线错误。结果数量使用 polite status，保存失败使用及时反馈并维持原收藏状态。加入生词的按钮同时有文本和 pressed 状态；未准备好 / 存储异常有禁用理由；当前设备无离线发音时显示原因，不做空播放。

**学习退出。** 普通练习：已提交题目保存后给明确计数；未提交选择若有草稿能力才能称草稿已保存，否则离开前明确说明；时间打卡另记。口语：录音保存 / 失败 / 放弃各有清楚路径。模考：保留当前截止时间与已持久化答案，退出只保存中断，失败提供重试 / 明确退出；不能用「退出后继续计时」之外的视觉暗示暂停。此处的交互设计范围是现有学习闭环，不是新增算法或记录云同步。

## 字体、尺寸和布局建议（项目建议，不是平台强制规范）

- 使用系统 UI 字体链 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`，鸿蒙由可用系统字体回退；正文 16 px / 1.65，词条正文可 17 px，题面与英文材料 18 px / 1.7，辅助信息 14 px / 1.5，必要标签不小于 13 px。不要打包或从 Apple 提取 SF 字体。
- 使用 rem 和自然高度，标题随宽度柔性变化；正文常规字重 400–500，标题 600–650；只在品牌或游戏预览中用装饰字体。英文 IPA 和中文回退应现场核对。
- 主要点击区域至少 44 × 44 CSS px，移动主要操作建议 48 px 高；图标可 18–22 px，但真实命中区域按上述尺寸。结果行与独立收藏按钮明确分离，至少 8 px 视觉间隔。
- 间距基准 4 / 8 / 12 / 16 / 24 / 32 / 48；手机外边距 20 px（320 宽时 16 px），桌面正文上限约 1120–1200 px，阅读列 620–720 px。避免用一排并列统计挤掉首屏主要操作。
- 关键题面、结果和错误都可自适应高度；320 CSS px 使用单列。桌面详情进入 / 关闭不改变列表列宽，避免搜索点击造成布局跳动。
- 底部导航仅在主层出现；练习 / 模考与词条详情的关闭和返回有上下文。软键盘可见时应收起主层底栏或参与布局，不只缩小整个页面。

## 已核实的官方无障碍要求

以下是 WCAG 2.2 成功准则及 W3C 官方说明；说明页是解释材料，规范以 [WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/) 为准。未核实本项目符合全部准则，也没有将 iPhone / HarmonyOS 7 的视觉灵感写成官方设计规格。

| 官方要求 | 本方案应提供的可验收材料 |
|---|---|
| 普通文本至少 4.5:1；大字至少 3:1，placeholder 同样要核对。[W3C 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 四主题正文、次要文本、主按钮、placeholder 逐对实算；渐变和图片上的文字按最不利底色核对 |
| 识别组件、状态或必要图形的信息与相邻颜色至少 3:1，停用组件有例外。[W3C 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) | 输入边界、焦点、选中 radio、收藏 pressed、图表关键标记；装饰细线无需伪称为功能边界 |
| AA 的指针目标最小 24 × 24 CSS px 或符合间距等例外；44 / 48 是本项目更宽松的体验建议。[W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 不以图标尺寸冒充 hit area；主题、收藏、关闭、音频等小控件复核 |
| 文字可放大到 200%；水平书写内容在等效 320 CSS px 宽重排，适用例外另判。[W3C 1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[W3C 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 导航、搜索、词条、解析、表单及错误信息放大不丢信息。题页图片可提供专门放大，不能让所有页面都双向滚动 |
| 用户改变行高、段距、字距、词距时不应丢内容；对应测试值为 1.5 倍行高、2 倍段距、0.12em 字距、0.16em 词距。[W3C 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | 高度非固定、中文英文长文本和底部按钮不重叠 |
| 键盘焦点不能被作者内容完全遮挡。[W3C 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) | Sticky 页头 / 底栏 / sheet 不遮焦点；焦点可见、开关弹层正确移动和返回触发控件 |
| 状态消息可以由辅助技术获知，而不必主动移焦。[W3C 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | 搜索数量、保存 / 同步状态用 status；重大错误用 alert；装饰 aria-hidden，题目英文 lang=en |

此外依规范验收键盘可操作、无键盘陷阱、语义标题 / label、非颜色独占状态。题面正确 / 错误应有图标和文字；进度图旁提供数字摘要或数据表。持续装饰默认静态，启用动画时提供关闭入口并响应系统减弱动态；不闪烁，不自动播放装饰声音。真实计时模考的考试规则和可访问练习模式应分别表达，不能随设计擅自放宽考试截止。
