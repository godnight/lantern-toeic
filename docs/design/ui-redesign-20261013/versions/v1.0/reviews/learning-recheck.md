## 已通过的产品层级与范围取舍

1. 首页第一主动作只对应一条真实队列；到期题、词卡和新题分别完成，不以一个按钮虚构自动学习旅程。原生/网页保存范围须继续来自真实状态。
2. 五项底栏保留进度，顶部查词有文本并具44px点击区域。查词/详情专注页返回来源，底栏不扩成六项。
3. 托业场景词与英汉查词两范围保留；范围切换保持输入，场景初始可浏览、通用词典空查询先提示输入。查词不意味着学习事件，只有用户收藏/自评形成记录。
4. 练习完组与时间打卡分开。表单没有扩成心情、错因或任务编辑；取消打卡保留已提交答案。保存成功状态在生产中必须由现有 `addCheckin` 成功返回支撑。
5. 没有到期不是删除错题；错题是按余力再练，提前复练不提高间隔，不形成补课债。
6. 本机题包、私人云题包、考试记录范围分开。模考解析留在原题包/题号上下文，普通原创题首答/复练不吸收模考浏览。

## 最后的小修订与文档同步

主代理收到以下具体建议；本文件读取时未取得修后截图，不能自动标为已关闭：

- 首页3题到期任务用明确review状态/来源进入session，和从复习页进入的标签相同。
- 词卡save-error须保留已翻释义和已选择反馈，避免「还未翻卡」与「反馈保存失败」并存。
- 模考保存失败处显示「本题未保存·请重试」，泛称自动保存不应掩盖该题失败。
- 打卡成功文案移除未存在的hook名 `saveCheckin`；实际hook为 `addCheckin`。用户界面可简单表达保存成功，具体名称留在内部规范。
- 正式文档更新二轮/修订核对入口、结论和首页当前步数。当前原型是词卡主任务加三项下一步，规格仍称「今日三步」；可以保持复习/薄弱Part/新词三个**学习阶段**，但需说明复习含词卡/题目两独立队列，不让“步数”与四条任务冲突。

上述可在代表稿与文档中完成，无需连接真实数据、增加API或改算法。旧制/现行预检、模考提交/退出保存失败、全来源返回/二批结果/跨账号切换应继续作为正式实施的明确门槛，不能静默落成统一默认fixture。
