## 结论

现有问题主要在信息组织与视觉分配，并非只缺一套更好看的配色。大场景、重复插画缩略图、全局状态横条和装饰性标题占据首屏；词库同时排列范围切换、场景下拉、收藏筛选和词卡入口，主任务不够明确。建议采用一套安静、清晰的学习界面骨架，并让四主题共享字体、网格、组件结构和语义状态。

默认日间和夜间应彻底移除游戏角色、游戏场景、地图名、丝线/圣巢等装饰引用。游戏主题仍需具体可辨认，但以有限的边缘艺术、主题预览和色彩表达；答题、搜索、词义阅读始终在纯色内容面上完成。

## 建议设计系统（项目提案，不冒充系统官方数值）

### 字体与信息层级

- 字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "HarmonyOS Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`。使用设备已有字体，不引入网络字体阻塞。HarmonyOS Sans 仅在实际存在时采用，不假定全部设备都有。
- 桌面页标题 32/40px、600；手机 28/36px、600。分区标题 20/28px、600。正文与题干 16/26px、400。按钮 15/22px、600；次要信息 14/21px。小于 12px 的信息文字不进入核心使用流程。
- 词头 24/32px、600；手机可为 22/30px。音标与词性 14/22px；释义 16/26px。长例句按正文显示，不强制单行。
- 数据大数 28/34px，使用 tabular numerals；单位与标签 14px。目标分数与已得分明确区分，禁止仅用 650+ 大数暗示用户成绩。
- 中文标题不拉开装饰字距。英文 Part/来源标签不用长串全大写加宽字距。品牌可保留小型标识，但品牌不能和页面标题争夺注意力。

### 网格、留白与密度

- 间距谱：4、8、12、16、24、32、48px。内容分区间 32px；块内标题到说明 8px；说明到操作 16px；列表行内 12/16px。
- 桌面侧栏 216–224px；顶部栏 64px；主内容最大宽 1120px，水平边距 32–48px。字典双栏的结果列约 360–400px，详情可伸展，但长正文每行约 65–75 个英文字符。
- 手机 320–430px：左右 16–20px，一列；底栏内容高约 64px 加安全区；正文末尾至少留底栏高度与 16px 间隔。320px 下不可通过缩小字体塞下工具栏。
- 768–1100px：侧栏折叠为短侧轨或抽屉，搜索详情切回单列；折叠屏布局按可用宽度重排，控件文字大小保持。
- 主要内容块圆角 16px，输入/按钮 12px，提示标签 6px。不要每个子区都再套卡片；用分隔线与小标题表达关系。默认无阴影，只有弹层或浮层使用单一轻阴影。

### 导航与各页布局

| 页面 | 第一视觉层 | 第二层 | 后续内容 |
|---|---|---|---|
| 今日 | 日期与简短标题；下一步任务；预计用时；开始操作 | 今日可选 2–3 项练习、到期复习 | 周学习摘要、计划调整；不要固定占首屏展示目标分数 |
| 单词搜索 | 页标题与全宽输入；查询范围小标签 | 结果数量与紧凑筛选；相近词纵向列表 | 选中结果详情；来源/许可折叠说明 |
| 单词详情 | 词头、词性、音标；发音与生词状态 | 常用义、搭配、已有例句 | 更多词典义、词源与来源；不存在的例句不补造 |
| 练习 | 题包/技能选择，预计时长，当前状态 | 听读/口语及 Part 分类 | 私人题包入口明确归属；不复制到普通资源列表 |
| 作答 | 小型题号/进度、题面、音频、选项 | 提交/下一题与保存状态 | 解析后再显示答案依据与相关词；游戏艺术完全退出题面 |
| 复习 | 到期总数和开始本组 | 错题、词卡两个队列；完成状态 | 延后/查看记录等辅助操作；不以红色大数制造负担 |
| 进度 | 时间范围与已记录学习摘要 | 首答正确率分 Part 图表；复练单独标识 | 日历/时间记录/手记；空数据明确“尚无记录” |
| 资料库 | 搜索/分类；本机题包、私人云库、公开资料的清楚分区 | 列表标题、来源、格式、可用状态 | 上传/下载/导入使用各自准确动词；空间不足、离线有明确状态 |

手机底栏固定为今日、练习、复习、进度、资料五项，短标签与 20–22px 同风格图标。查词固定在顶栏，进入搜索后保留“查词”清楚标题；练习中的查词应保存当前位置，关闭后回到原题。桌面查词可在侧栏一级入口或全局顶栏固定入口，不藏在资料深层。

### 组件状态

- 主按钮：纯色填充 + 清楚文字；每个内容区域只设置一个主操作。次按钮纯色面/描边；低优先级用文本按钮。所有触控目标建议至少 44×44 CSS px，这是本项目舒适目标。
- 输入：始终有可见标签；placeholder 为举例，不替代标签。焦点显示 2px 环及 2px 间隔。清空按钮有名称。加载时保留当前查询和结果容器高度；错误提示贴近输入。
- 结果行：hover 为轻表面变化；选中用窄边标记 + 背景 + `aria-selected`；收藏状态有文字或可读名称。不要整行隐形按钮叠加多个未知操作。
- 错误/成功/警告：图标 + 标题/文本共同表达。游戏主题主色不能兼任错误色；丝之歌红色选中/主按钮不得与错误提示共用唯一视觉语义。
- 骨架：静态或轻淡入，不闪烁。空结果给“更换关键词/清除筛选”等匹配当前上下文的操作，不给会切换范围的含糊“查看全部”。
- 对话框：手机详情宜独立全屏；设置/主题为底部 sheet；桌面居中弹层 560–720px。关闭键固定，长内容内滚动，键盘焦点可返回触发入口。

## 四套主题提案

以下为可供首版视觉稿采用的配色方向，最终 token 需逐项计算对比度后冻结。主题不更改信息层级、字号、布局、功能名称或学习状态。

| 主题 | 背景 / 内容面 / 主字 / 次字 / 强调 | 艺术与材质 | 限制 |
|---|---|---|---|
| 日间·清昼 | `#F6F7F9` / `#FFFFFF` / `#18212F` / `#586474` / `#335DDA` | 纯色、清楚分隔、极轻层次；稳定中性蓝强调 | 无游戏图像、地图、纹样、人物、粒子、游戏引用文案 |
| 夜间·静夜 | `#101318` / `#1A1F27` / `#F1F4F8` / `#B3BECD` / `#91ADFF` | 深中性灰、内容面轻抬亮；降低大白块刺眼感 | 无游戏元素；不以纯黑+发光边框营造科幻感 |
| 空洞骑士·圣巢 | `#111A24` / `#1B2937` / `#EEF4F8` / `#B4C6D7` / `#A3CCD9` | 冷灰蓝、骨白、小型遗迹轮廓；可在主题页预览原创场景 | 不使用官方角色/原画作为核心控件，不把每页命名为地图区域；题面、输入、详情无纹样 |
| 丝之歌·绯丝 | `#20181B` / `#2E2328` / `#F5EEEE` / `#D0BCC5` / `#E0A8B2` | 暖灰、绯红、象牙色；页边可有静态细丝线/钟形轮廓 | 红色主色与错误色用图标/形状/文字明确区分；避免满页红黑压迫感、粒子与背景闪烁 |

主题艺术在今日页可作为桌面右侧窄幅、完全独立于文字的静态小区域；手机可放在内容末尾或外观页。建议设计稿给出“有艺术 / 关闭艺术”两种同布局状态，不用透明玻璃覆盖背景图。

主题切换使用四张同尺寸、同一页面内容的微缩预览，名称、明暗描述、选中勾标完整；日间/夜间纯界面预览，两个游戏主题显示小型艺术。另提供“日夜跟随系统”开关仅用于默认日/夜配对，避免把第五张“系统”误读成第五套主题。应用后不改变滚动、输入、作答或录音状态。

## 动效策略

按压反馈 80–120ms；状态淡入 120–160ms；sheet/对话框进入 180–220ms。动效只解释状态变化，主操作按钮、正确率图表、题目不循环发光或漂浮。页面切换保留焦点/上下文，不用长距离滑行。四主题均默认没有粒子、雨、水面、呼吸光。用户开启减少动态时去除非必要位移、滚动与装饰动画，反馈可以瞬时显示。

## 可访问性与性能

已核实：WCAG 2.2 AA 普通文字最低对比度 4.5:1，大字 3:1。来源：[W3C 对比度理解文档](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这包含 placeholder、悬停和焦点文字；正式比值按最终前景/背景计算，不能以截图观感代替。

项目验收还应覆盖：输入/控件边界和可见焦点、键盘顺序、200% 字号、320px 无横向溢出、中文/英文长文换行、屏幕阅读器的页标题与状态通告、软键盘与安全区、减少动态、四主题所有异常态。低对比“精致灰”不能承载次要但必要的信息。

不增加网络字体或首屏大图；主题样式是 token 切换；游戏图片延迟加载、固定尺寸防布局跳动、可完全关闭。搜索结果用有限列表与已有按需加载，不把 84,979 条词典条目一次性做成 DOM。首屏艺术建议手机 0 字节、桌面延后加载；视觉方案不扩大媒体包。

## 第一轮评审分歧与修订要求

1. **美术辨识度与专注度**：视觉评审支持游戏主题有识别度，但反对重复场景、图像导航、题面背景。建议修订为静态边缘艺术 + 外观页大预览，主内容始终纯色。两默认主题无需对应游戏世界观。
2. **卡片与列表**：今日下一步任务可以一个主块；搜索结果、资料和练习目录应采用紧凑列表。大量同级卡片会回到旧界面的问题。
3. **查词位置**：视觉评审支持固定入口；若手机五项底栏已满，不添加第六个图标，也不能再次藏进资料深处。顶栏“查词”需文字或固定可读图标，导航页位置一致。
4. **首页数据密度**：目标分数、考试天数、周启动、总题量不应全挤在永久顶栏。今日页只保留当前决策需要的数据；目标可在计划入口和进度页查看。
5. **日夜跟随系统**：四套主题不应再增加“水晶山峰”等历史第五皮肤。跟随系统仅为日夜策略，和选主题分开。

## 第二轮原型验收清单

- 同一搜索结果或练习页面四主题并排，不能只以四张首页表皮代表一致性。
- 桌面 1440 与手机 390/320 均能判断导航、主操作、列表和详情。
- 首页、搜索/结果/详情、练习目录与作答、复习、进度、资料库均有代表稿。
- 加载、空结果、离线、词典加载失败、不可用音频、记录保存失败、资料空间不足、主题切换选中与焦点状态均有可见样稿或可操作状态。
- 默认日夜中零游戏素材；游戏主题的题干、选项、词义和输入无背景艺术。
- 第一个屏幕就能找到主任务；没有同级多个主按钮；文字层级、间距、对齐和列表密度一致。
- 方案中的状态语义与已有账号/本机/云库边界保持，未虚构学习成绩、例句、数据或额外功能。

当前建议：按以上方向形成隔离原型再复评。尚未看到新原型，不应把本轮结论记成“视觉设计已通过”。
