# 分级验证与发布

按改动风险选择检查，不按版本号大小机械决定。一次按钮修改不自动变成全 App 验收。开发、测试、发布共同使用本页；历史阶段记录不追加当前门槛。

## 工程边界

| 层 | 主要位置 | 关注点 |
| --- | --- | --- |
| 展示与交互 | app/learn、components、CSS、主题素材 | 布局、阅读、点击、焦点、禁用状态 |
| 学习与业务 | lib、hooks、学习状态和评分逻辑 | 首答/复练、SRS、数据一致性 |
| 服务与存储 | app/api、db、drizzle、worker | 身份隔离、事务、迁移、托管媒体 |
| 原生适配 | harmony、mobile | ArkWeb、权限、生命周期、离线资源 |
| 内容与媒体 | content、public/audio、art | 修改内容的正确性、来源与播放 |
| 工程交付 | .github、构建/签包工具、docs | 可重复构建、明确版本和实际发布结果 |

不为分层移动已有业务文件。跨层依赖改变时提高验证等级；纯文档、版本号递增和交件元数据修正不自动提高等级。

## 四个等级

| 等级 | 例子 | 本次必做 | 默认不做 |
| --- | --- | --- | --- |
| L0 文档/流程 | 文档、说明、独立工具配置 | 文档一致性；工具改变时只跑受影响的工具测试 | 产品全测、Web/App 构建、签名、安装 |
| L1 局部界面 | 两个按钮、间距、页面文案 | 类型/相关组件检查；看实际改动页面；确认点击、必要的窄屏/大字号与焦点；构建需要交付的端 | PDF、整套考试/词典、音频全库、原生辅助工具矩阵、全页面截图 |
| L2 单模块功能 | 一个明确模块的缺陷修复 | 复现原问题、修复回归、相关边界与相邻接口；构建受影响端 | 未受影响模块重测、全量媒体重审 |
| L3 大版本/高风险 | 跨模块改造、身份/隔离、SRS、持久化迁移、原生桥、依赖/工具链更新 | 完整自动回归和相关端关键流程；新增风险的专项验证 | 给无关工具重签、多个角色重复扫同一包 |

CI 当前只对明确列出的文档、局部 UI、流程/签包工具和 Web 主题测试选择快速路径；普通业务模块尚未建立自动定向映射，仍保守走完整路径。未知路径或无法证明是纯版本元数据时保守走完整路径；分类失败必须报错，不能伪装为“文档无需检查”。main 与显式全量触发保留完整检查。用户声明的大版本使用全量入口。

PR 使用相对基线的累计差异，包括删除与重命名前后的路径。不能只看最后一笔提交，让早先未验证的业务变化被后续文档提交掩盖。小改以最近已验收的集成分支建立短 PR，避免把一个旧的大 PR 无限续写；不擅自合并既有 PR。

CI 的快速路径由 `.github/scripts/change-scope.mjs` 选择；签包工具入口见 [使用说明](../tools/harmony-release/README.md)。仅修改测试等待逻辑时，只验证该测试；工具测试通过不代表新 App 已验收。

## 一次构建、按产物签名

- Web 改动只发布 Web 时，不构建或签 HAP。App 交付才构建 Shared 和 HAP。
- Web 托管构建与 App 离线构建是不同目标；每个需要交付的目标各构建一次，不在多个工作目录重复构建同一个目标。
- 只对最终可安装 HAP 使用原证书签名一次，并做一次官方验签。该次验签可以同时覆盖包签名和 code-sign，不拆成重复签名。
- Python、Node、Java、SDK、辅助脚本、source/Shared/Web ZIP 不需要用 App 证书签名。已有 SDK 和证书直接复用；工具或配置改变时才重新核对对应部分。
- sign 自身已有预检时，不再默认先独立执行 check 再 sign。check 是按需的 dry-run，不是每次发布的额外前置。
- 版本号、输出路径和制品身份作为请求参数传入稳定工具；不再为了 20058 → 20059 复制一套工具、重新跑整个工具矩阵。
- 正常 Shared 同步已核资源一致性时，不再紧接着完整 check:web。独立检查命令保留，供包被外部修改、传输异常或排障时使用。
- 原位升级保留数据；不为验收卸载或清空用户数据。设备回读版本和启动成功即可证明升级，不冒称逐条学习数据或全 App 已验。

## 共用一份结果

开发完成适用检查；独立复核只看本次变化及尚缺的证据；发布者引用同一结果。Git 提交与 delta 说明源码变化，最终制品记录一次 SHA；正常交接不重复遍历未变的全部音频、全部源码或每个工具。

一份 PR 说明或简短发布结果足够，包含：改了什么、等级和理由、实际做的检查及结论、源码/产物版本、已知剩余问题、发布/安装结果。不要层层生成 ENTRY → PINS → RECEIVED → CLOSEOUT 来互相证明。

未变模块可以继承原验证结果，明确标为“继承”，不冒称新跑。源码或产物实际改变才重做受影响检查；只修清单路径、父提交归属或文字说明，不重新构建或签名。

仅因具体差异、实际失败或新发现风险扩查，并说明原因。无关已知问题继续记录，不阻挡无关的小改发布。补充性的全量 CI 可以后台完成，不能把“仍运行”写成“已通过”，也不默认成为 L1 发布关卡；所选等级的必要检查仍需通过。

## 接续与协作

先读当前状态和本页，再读相关源码/角色。不要默认扫描全部历史记录、重新安装依赖、启动全套工具测试。依赖与锁文件未变化且已有可用环境时复用环境。

遵循用户已有授权：已授权的推送、发布和原位升级无需重复征求确认；真实运行时拒绝或缺少必要授权时如实处理。测试通过与用户视觉认可分别记录，不因此额外制造批准环节。

保持一个产品写入者、一个发布者；简单任务不安排多个角色重复相同核验。默认不创建 tag；签名材料、密码和服务凭据不得进入源码、命令行或交付说明。
