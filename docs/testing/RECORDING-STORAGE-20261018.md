# Recording upload consistency — 2026-10-18

Based on CT r20 `42ec27e8c6e41a04014e5a78a52befce7f97b1e7`. Sites identity and the existing owner/origin gates are retained. No database migration, production cleanup, authentication switch, microphone capture or recording conversion is included.

Uploads use a private UUID object key per request. The existing globally unique recording row selects the winner. Before acknowledging an upload, the server verifies the referenced object's bytes, SHA-256 and MIME together with the canonical client metadata (prompt, practice time, duration, MIME and note). The server-generated title/upload time do not change retry identity. Same-content retries succeed without rewriting the object; changed content or another owner returns 422. Pre-upgrade object keys remain readable and are checked without migration or replacement.

An insert exception does not prove rollback: the server reads the actual winner before deciding success or cleaning up. Cleanup only touches the current request's unique unreferenced object key. If the insert result and readback are both unavailable, the response is 503 and the object is retained, since it may already be referenced. Failed cleanup can also retain an unreferenced private object. This protects committed recordings but does not claim a distributed transaction or guarantee zero orphan objects during service outages. No bucket scanning or deletion of old objects is performed.
