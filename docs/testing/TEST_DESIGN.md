# 微光托业跨端测试设计

初版日期：2026-09-08；更新日期：2026-09-13。文档保留 Web/PWA、Android、iOS、HarmonyOS 的 40 个历史风险场景；自RFC 0001起，当前发布门禁只覆盖Web/PWA与HarmonyOS，Android/iOS场景仅作归档参考。实际结果与限制见 [v0.2.4测试执行报告](TEST_EXECUTION_v0.2.4.md)。不得把设计中的预期视为已经通过。

## 1. 判定口径与平台边界

- **P0**：阻断主学习流程、已确认保存的数据丢失、串账号、录音无法可靠停止或保存；相关平台发布前必须通过。
- **P1**：内容/主题/布局/安装更新与恢复体验的重要问题；影响录音或数据完整性时升级 P0。
- **L1 源码行为**：运行实际 TS/TSX，模拟 React hook、时钟、网络和存储。**L2 产物**：类型/内容/构建/资源与迁移校验。**L3 浏览器**：实际 DOM、LocalStorage、IndexedDB、网络和 SW。**L4 平台编译**：Android/iOS/Harmony SDK 编译及签名。**L5 设备**：真实系统权限、WebView、安装升级、音频及前后台。高层通过不免除其依赖的检查，低层通过不等于高层通过。
- 自动化与手工均须记录用例 ID、实际平台/系统/WebView 或浏览器版本、输入、预期/实际、通过/失败/阻塞、证据路径。失败记录实际结果，缺工具记阻塞；没有执行记未测。

| 平台 | 本版支持契约 | 必须独立留证 | 当前明确边界 |
|---|---|---|---|
| Web | 托管身份 + D1 记录 + R2 录音；账号分区的本机队列 | 授权测试身份、真实 API/缓存策略与跨设备合并 | 开发预览不能证明生产托管身份与 D1/R2 正常 |
| PWA | 与 Web 同一身份成功同步后的记录互通 | Chrome 系安装、iOS Safari 添加桌面、独立窗口权限与存储 | 在线初次载入；已打开页面可离线记；离线冷启动应为说明页 |
| Android | Capacitor 8 本地资源，共享 React；owner=null | APK 编译、签名指纹、安装升级、Android WebView/录音 | 没有原生登录/云同步；临时 CI debug 签名不保证覆盖升级 |
| iOS | Capacitor 本地资源，共享 React；owner=null | 无签名模拟器编译与已签名真机安装分别记录 | 模拟器编译不等于 iPhone 包；导出/分享与真机音频未验收 |
| HarmonyOS | ArkTS/ArkUI/ArkWeb；固定本地来源 `https://lantern.local`；owner=null | SDK 编译、已签名 HAP、API/机型、原生桥事件时序 | 目标 5.0/API 12+；共享网页资源校验不生成 HAP，当前无可安装 HAP |

最小设备覆盖：桌面 Chromium + Safari/WebKit；Android Chrome PWA + 原生 APK；iPhone Safari PWA + 原生；用户主要使用的 HarmonyOS 手机优先。手机型号/系统未知时先记录未知，不猜测兼容。共享界面先覆盖 360×800、390×844、768×1024、1440×900；再补 320px 窄屏、横屏、系统大字体/页面放大。L3 模拟窄屏不能替代 L5 安全区和键盘验收。

## 2. 测试前置与可核对数据

仅使用隔离测试数据、授权测试账号和可丢弃测试设备数据。A/B 两账号测试须用正常认证，或在隔离本地测试环境注入可信身份的测试替身；不得向生产伪造身份头。线上个人学习记录不做故障注入或破坏性清理。

准备一份“记录账本”：1 个首次错答 qid、同题复练答对、另一个首次答对、1 条 5 分钟打卡、1 条带资源 ID 的打卡、1 段 3–5 秒录音、1 次设置/主题变更；保存各 ID、原始发生时间与录音哈希。原生使用 device 分区，Web 使用 A 分区。账号 B 从空数据开始。升级、离线恢复、重开之后逐项核对账本，不能只看“已同步”或题目总数。

需要故障注入的场景在隔离 fixture 中控制：本机写失败、IndexedDB 事务失败、400/413/429/503/401/409、连接超时、响应体迟到、先后乱序、重复成功响应。旧数据迁移使用 v0.2.0/v0.2.1 导出的测试 fixture，保留不可变原件。JSON 导出本版不含音频字节，也没有完整恢复 UI，不能称为完整备份。

## 8. 现有自动化如何复用

本版包含35项学习/录音/同步、鸿蒙入口与平台范围行为回归、4项UI组件CSS/语义测试及1项生产HTML测试。最终状态以执行报告和日志为准。测试运行实际模块，但React、媒体、存储、网络和部分UI是替身。它们可以为L1提供证据，不能证明真实权限、身份、数据库部署或设备数据保留。

## 9. 每版执行顺序

1. **根代理当前可做（约一轮浏览器测试）**：L01→L02真实错答/复练/打卡闭环，保存前后截图与ID账本；L08导出三文件隔离；U01/U02三主题+手机素材库+弹窗/键盘模拟；L07一项官方资源打卡。浏览器麦克风环境如可用再做R01/R04；虚拟音频只标流程通过。
2. **根代理构建门禁**：typecheck、content、art、35项行为回归、Web+5项构建后测试、共享网页、H共享资源和工具链报告。已获得足够相关证据就停止重复全量运行。只读代理不运行会改checkout的构建/资源脚本。
3. **价值最高的新增自动化**：D07服务端答案重算/授权/幂等；P02 SW缓存边界；L06作答及设置写失败保持草稿；D10单项损坏不抹去合法日志。使用实际源码和隔离fixture，测试业务结果，不复制实现。
4. **需要授权测试环境的L3**：D02真实离线→D1/R2回传→第二客户端核对；D06真实身份切换；P03旧SW升级。若没有正常认证的B账号或独立测试站，标阻塞，保持现有L1证据，不伪造生产身份。
5. **鸿蒙交付前必须做**：使用目标Harmony机型，先L4真实HAP编译签名，再R01–R07、H01/H02、D01、P05、P06；Android/iOS为归档平台，不属于当前交付。缺设备/签名/SDK是阻塞，不能由浏览器/CI替代。

## 10. 设计阶段风险清单（修复与执行状态以报告为准）

- 起读时 `app/study-app.tsx` 的普通选题走 `chooseQuestions`，而 `startReview()`直接筛选错题/到期题、单条复习直接`setQueue([q])`。设计期间已观察到集成负责人新增完整复习题组回归；该项按“发现→修复中→最终L3验证”跟踪，不能再引用为最终版仍存在的缺陷。
- `lib/use-study.ts` 的`recordingUrl()`在本机Blob缺失时统一回退`/api/recordings?id=...`，未按owner区分；native无账号，因此D08需检验失败是否有明确提示，不能只显示无声播放器。
- `readSnapshot()`外层catch会回空数据；一个坏的录音元数据或profile可能影响合法日志重建。D10应先在隔离fixture测试，不对真实记录注入损坏。
- `installHarmonyHost()`只在固定Harmony origin安装桥；Android/iOS主要依赖`visibilitychange`，未见Capacitor App插件返回/状态接线。R03/R04需单独验证两端实际行为。
- `public/sw.js` 的cache名仍为`lantern-public-v2`且静态资源cache-first；新版是否更换同路径资源需要由P03实测，不能只验证新浏览器首次加载。
- `app/learn/speaking.tsx` 保存失败后仍允许“再说一次”；R05需检验用户是否会在原Blob未保存时无提示覆盖它。
- 原创题包导出中的版本字段为`0.2.0`，页面页脚为`v0.2`，源码版本为`0.2.2`；L08应区分内容包版本与应用版本是否有明确约定，不单凭不同字段断言错误。
